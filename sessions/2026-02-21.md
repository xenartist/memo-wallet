## 功能实现：Receive 接收功能

### 需求分析

用户希望实现钱包的接收功能，让其他用户可以扫描 QR 码或复制地址来转账。经过讨论，确定了简洁的设计方案：

- 不区分 X1 和 Solana 网络（地址相同）
- 只显示 QR 码和地址，保持界面干净
- 接收历史留待未来 Activity 独立页面实现

### 技术选型

**QR 码生成库**：

- 选择 `react-native-qrcode-svg` (v6.3.21)
- 依赖 `react-native-svg` (v14.1.0)
- 理由：轻量级、纯 JS 实现、无 NDK 依赖、与项目环境兼容

**兼容性问题**：

- 初始安装 `react-native-svg` v15.15.3 导致编译错误
- 问题：与 React Native 0.74.6 不兼容（API 不匹配）
- 解决：降级到 v14.1.0，成功编译

## 功能实现：Swap 确认对话框 + From Token 自动切换 To Token

### 需求分析

1. Swap 功能在真正签名前需要确认对话框（类似 Send 的确认流程）
2. X1 网络手续费显示固定 ~0.001 XNT（xDEX API 内部处理 CU）
3. Solana 网络手续费显示 ~0.0001 SOL（基于实测）
4. From token 切换时，To token 应自动切换为合适的默认配对

### 一、Swap 确认对话框

#### 实现思路

- 添加 `showSwapConfirmModal` state
- 添加 `handleConfirmSwap()` 函数做前置验证，通过后显示对话框
- `handleExecuteSwap()` 从对话框的 Confirm 按钮触发
- Swap 按钮 `onPress` 从 `handleExecuteSwap` 改为 `handleConfirmSwap`

#### 确认对话框内容

```
┌────────────────────────────┐
│      Confirm Swap          │
│                            │
│  From   1.0 XNT            │
│  To     100.0 MEMO         │
│  Rate   1 XNT = 100 MEMO   │
│  Network  X1               │
│  Est. Fee  ~0.001000 XNT   │
│                            │
│  [Cancel]    [Confirm]     │
└────────────────────────────┘
```

#### 手续费显示策略

| 网络             | 显示手续费  | 说明                         |
| ---------------- | ----------- | ---------------------------- |
| X1 (xDEX)        | ~0.001 XNT  | 固定值，xDEX API 内部处理 CU |
| Solana (Jupiter) | ~0.0001 SOL | 基于实测值                   |

#### Send 确认对话框修复

同时修复了 Send 确认对话框手续费未显示的问题：
在 `handleConfirmSend()` 中补充了手续费估算赋值：

```typescript
const estimatedFee = sendToken.network === 'X1' ? 0.001 : 0.0001;
setSendFeeEstimate(estimatedFee);
```

### 二、From Token 自动切换 To Token

#### 切换规则

1. 默认进入：XNT → MEMO
2. From = XNT → To = MEMO
3. From = 非 XNT 的 X1 token → To = XNT
4. From = SOL → To = solXEN
5. From = 非 SOL 的 Solana token → To = SOL

#### 问题排查过程

**第一次尝试**：依赖 `networkChanged` 条件判断  
→ 只处理了跨网络切换，同网络内切换不生效 ❌

**第二次尝试**：增加 `shouldUpdateToToken` 多条件判断  
→ 逻辑过于复杂，引入新 bug ❌

**最终方案**（用户建议）：逻辑彻底简化，每次选择 From token 时无条件执行：

```typescript
const handleSelectFromToken = (token: SwapToken) => {
  setSwapFromToken(token);
  setSwapNetwork(newNetwork);

  if (token.network === 'X1') {
    if (token.symbol === 'XNT') {
      // XNT → MEMO
    } else {
      // 非XNT → XNT
    }
  } else {
    if (token.symbol === 'SOL') {
      // SOL → solXEN
    } else {
      // 非SOL → SOL
    }
  }
};
```

#### 第二个 Bug：unknown token 问题

**现象**：从 SOL/MEMO/USDC 切换后，To token 显示为 unknown  
**原因**：`swapTokenList` 是异步加载的，切换时列表可能还是空数组，`find()` 返回 `undefined`

**解决方案**：优先使用立即可用的默认常量，找不到再 fallback 到 `swapTokenList`：

```typescript
// X1 网络：优先使用默认常量
const memoToken =
  DEFAULT_TO_TOKEN ||
  swapTokenList.find(t => t.symbol === 'MEMO' && t.network === 'X1');

const xntToken =
  DEFAULT_FROM_TOKEN ||
  swapTokenList.find(t => t.symbol === 'XNT' && t.network === 'X1');

// Solana 网络：优先使用硬编码的 solanaDefaultTokens
const solXENToken =
  solanaDefaultTokens.find(t => t.symbol === 'solXEN') ||
  swapTokenList.find(t => t.symbol === 'solXEN' && t.network === 'Solana');

const solToken =
  solanaDefaultTokens.find(t => t.symbol === 'SOL') ||
  swapTokenList.find(t => t.symbol === 'SOL' && t.network === 'Solana');
```

#### 数据源说明

| 数据源                | 可用时机       | 用途                            |
| --------------------- | -------------- | ------------------------------- |
| `DEFAULT_FROM_TOKEN`  | 立即（常量）   | XNT 默认 token                  |
| `DEFAULT_TO_TOKEN`    | 立即（常量）   | MEMO 默认 token                 |
| `solanaDefaultTokens` | 立即（硬编码） | SOL/solXEN 等 Solana 常用 token |
| `swapTokenList`       | 异步加载后     | 完整 token 列表，含余额         |

### 经验总结

1. **复杂逻辑不如简单逻辑** - `networkChanged`/`shouldUpdateToToken` 多条件判断不如直接无条件执行
2. **异步数据要有 fallback** - 依赖异步加载的数据时，必须提供同步的 fallback 值
3. **X1 和 Solana 保持一致的处理模式** - 都优先使用本地立即可用数据，再 fallback 到异步列表
