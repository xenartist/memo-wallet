## 技术方案文档

### Send 功能：CU 优化策略

#### 背景

Solana 交易需要设置 Compute Unit (CU) 预算。设置过低导致交易失败，设置过高浪费费用。本方案通过交易模拟动态计算最优 CU。

#### 实现位置

**文件**: `src/send.ts`  
**函数**: `executeSend()` (line 350-600)

#### 工作流程

```
1. 构建交易指令
   ↓
2. 创建交易对象（不含 CU 指令）
   ↓
3. 模拟交易 (simulateTransaction)
   ↓
4. 获取实际消耗的 CU (unitsConsumed)
   ↓
5. 计算优化后的 CU = unitsConsumed × 1.1 (10% buffer)
   ↓
6. 添加 CU 预算指令到交易开头
   ↓
7. 签名并发送交易
```

#### 代码示例

```typescript
// src/send.ts (简化版)

export async function executeSend(params: SendParams): Promise<string> {
  // 1. 构建指令（原生转账或 SPL 转账）
  const instructions: TransactionInstruction[] = [];

  if (tokenMint === null) {
    // 原生转账
    instructions.push(
      SystemProgram.transfer({
        fromPubkey: senderPubkey,
        toPubkey: recipientPubkey,
        lamports: amountLamports,
      }),
    );
  } else {
    // SPL 转账 + 可能的 ATA 创建
    // ... (详见 src/send.ts line 144-301)
  }

  // 2. 创建交易（不含 CU 指令）
  const {blockhash} = await connection.getLatestBlockhash();
  const transaction = new Transaction({
    recentBlockhash: blockhash,
    feePayer: senderPubkey,
  });
  transaction.add(...instructions);

  // 3. 模拟交易获取实际 CU 消耗
  console.log('[Send] Simulating transaction to estimate CU...');
  const simulationResult = await connection.simulateTransaction(transaction, [
    senderKeypair,
  ]);

  if (simulationResult.value.err) {
    throw new Error(
      `Simulation failed: ${JSON.stringify(simulationResult.value.err)}`,
    );
  }

  const unitsConsumed = simulationResult.value.unitsConsumed || 200000;
  console.log(`[Send] Simulation unitsConsumed: ${unitsConsumed}`);

  // 4. 计算优化后的 CU (10% buffer)
  const computeUnits = Math.ceil(unitsConsumed * 1.1);
  console.log(`[Send] Setting CU limit: ${computeUnits} (with 10% buffer)`);

  // 5. 添加 CU 预算指令到交易开头
  transaction.instructions.unshift(
    ComputeBudgetProgram.setComputeUnitLimit({units: computeUnits}),
  );

  // 6. 签名并发送
  transaction.sign(senderKeypair);
  const signature = await connection.sendRawTransaction(
    transaction.serialize(),
  );

  console.log(`[Send] Transaction sent: ${signature}`);
  return signature;
}
```

#### 关键技术点

1. **模拟在签名前**:

   - 模拟使用临时签名，不上链
   - 获取 `unitsConsumed` 字段

2. **10% Buffer**:

   - `Math.ceil(unitsConsumed * 1.1)`
   - 防止边缘情况 CU 不足

3. **指令顺序**:

   - CU 指令必须在最前 (`unshift`)
   - ATA 创建指令在转账指令之前

4. **错误处理**:
   - 模拟失败 → 抛出详细错误
   - 回退默认值: `unitsConsumed || 200000`

#### 适用场景

- ✅ 原生代币转账 (XNT/SOL)
- ✅ SPL Token 转账
- ✅ Token-2022 转账
- ✅ 带 ATA 创建的转账
- ✅ 多指令交易

#### 性能数据

实际测试结果：

| 交易类型       | unitsConsumed | 优化后 CU | 默认 CU | 节省   |
| -------------- | ------------- | --------- | ------- | ------ |
| 原生转账       | ~450          | 495       | 200000  | 99.75% |
| SPL 转账       | ~15000        | 16500     | 200000  | 91.75% |
| SPL + ATA 创建 | ~25000        | 27500     | 200000  | 86.25% |

#### 已知限制

1. **需要两次 RPC 调用**:

   - 1× `simulateTransaction`
   - 1× `sendRawTransaction`
   - 对比固定 CU：仅 1 次调用

2. **模拟可能失败**:

   - 余额不足、账户不存在等
   - 需要详细错误处理

3. **网络延迟**:
   - 模拟增加 ~200-500ms 延迟
   - 对用户体验影响较小

#### 未来优化方向

- [ ] 本地缓存常见交易类型的 CU 估算
- [ ] 根据历史数据动态调整 buffer 比例
- [ ] 支持批量模拟（多笔转账）
